# static-host

Проект сервиса публикации готовых статических сайтов через MCP. Локально доступны кабинет единственного владельца, ключи агентов и MCP Streamable HTTP. Публикация сайтов и развёртывание ещё не реализованы.

## Запуск

Требуются Go 1.27.4 или новее, Node.js 24 и свободный порт 8081. Перед запуском Go необходимо собрать интерфейс:

```sh
npm --prefix web ci
npm --prefix web run build
read -r -s -p 'Password: ' PW; printf '\n'
printf '%s\n' "$PW" | go run ./cmd/static-host owner init --login admin --data-dir ./data
unset PW
go run ./cmd/static-host --data-dir ./data
```

Пароль — 12–72 байта. Для сброса используйте `owner reset-password --data-dir ./data` и передайте новый пароль одной строкой через stdin. Сброс завершает браузерные сессии, но не отзывает ключи агентов.

Кабинет доступен на `http://127.0.0.1:8081/`. Новые ключи по умолчанию бессрочные; можно задать срок в днях, повторно показать или скопировать значение, отозвать или удалить ключ. Ключ даёт полный доступ агента к MCP по `Authorization: Bearer <ключ>` на `/mcp`; отзыв и удаление действуют на следующий запрос. Значения старых ключей, выпущенных до поддержки повторного просмотра, восстановить нельзя. Инструменты публикации пока отсутствуют.

Новые значения ключей зашифрованы в SQLite с помощью AES-256-GCM. Файл `agent-key-encryption.key` в каталоге данных необходим для их восстановления: храните и резервируйте его вместе с БД, не раскрывайте и сохраняйте права 0600. Процесс с доступом к обоим файлам может прочитать ключи; это не защита при полном захвате сервера.

SDK Go v1.8.0: при протоколе по умолчанию `2026-07-28` его `ClientSession.Ping` не добавляет обязательные метаданные и получает 400; для этого клиента можно явно выбрать `ClientSessionOptions{ProtocolVersion: "2025-11-25"}`. Поддержка версий сервером не ограничена.

Интерфейс собирается из общих Vue-примитивов в `web/src/components/ui/` с утилитами Tailwind CSS; семантические токены темы определены в `web/src/style.css`.

Настройки: `--listen` / `STATIC_HOST_LISTEN` (по умолчанию `127.0.0.1:8081`), `--data-dir` / `STATIC_HOST_DATA_DIR` (`./data`), `--base-domain` / `STATIC_HOST_BASE_DOMAIN` (пусто). Явный флаг имеет приоритет над окружением. Owner-команды используют только настройку каталога данных. Без домена разрешён только числовой loopback IP; например `--listen 127.0.0.1:7778`. При заданном домене кабинет доступен по `https://panel.<домен>`, MCP — по `https://mcp.<домен>/mcp`; TLS должен завершаться внешним прокси с сохранением Host, внутренний listener остаётся HTTP. DNS и прокси настройка не выполняются приложением.

Проверка состояния:

```sh
curl --noproxy '*' http://127.0.0.1:8081/healthz
```

Ответ: `ok` и перевод строки. Остановить сервер можно с помощью Ctrl+C или SIGTERM.

## Контейнер и Uncloud

Образ собирается для `linux/amd64`: `docker build -t static-host:smoke .`, затем `bash scripts/container-smoke.sh static-host:smoke`. Smoke использует временные Docker volumes и не затрагивает `./data`. Образ работает от UID/GID 10001, хранит данные в `/data` и слушает `0.0.0.0:8081`; для запуска сервера требуется `STATIC_HOST_BASE_DOMAIN`. Listener можно переопределить через `STATIC_HOST_LISTEN`.

`compose.yaml` предназначен для одного экземпляра на выбранной ноде Uncloud. Скопируйте `.env.examples` в `.env` и укажите свои `STATIC_HOST_BASE_DOMAIN` и `STATIC_HOST_MACHINE`; образ и каталог данных `/var/lib/static-host` заданы в Compose. Caddy получает только маршруты `panel.<домен>` и `mcp.<домен>`; DNS, TLS и глобальная конфигурация Caddy здесь не меняются. Обновление stop-first допускает простой; не запускайте две копии с одной SQLite.

На выбранной ноде заранее создайте **новый** каталог данных с владельцем `10001:10001` и правами `0700`: `sudo install -d -m 0700 -o 10001 -g 10001 /var/lib/static-host`. Не применяйте эту команду к существующему произвольному каталогу. Только для новой базы инициализируйте владельца:

```bash
read -r -s -p 'Password: ' PW; printf '\n'
printf '%s\n' "$PW" | docker run --rm -i --mount type=bind,src=/var/lib/static-host,dst=/data ghcr.io/pavlenkoia/static-host:latest owner init --login admin
unset PW
```

Существующую базу повторно не инициализируйте; при необходимости используйте `owner reset-password` с тем же mount и паролем через stdin. Храните резервные копии SQLite и `agent-key-encryption.key` вместе вне ноды и проверяйте восстановление. При отсутствии владельца сервер завершится с ошибкой.

После подготовки и отдельного разрешения на развёртывание: `uc deploy -f compose.yaml --no-build`. Это не настраивает DNS или глобальный Caddy и не проверяет доступность кластера.

Workflow **Container image** выполняет проверки и smoke на push, PR и ручном запуске; публикует в GHCR только для default branch после успешного smoke. Теги — `sha-<полный SHA>` и `latest`. После первой публикации владелец должен один раз выбрать package → **Change visibility → Public**, затем подтвердить публичность анонимным `docker pull ghcr.io/<owner>/<repo>:<tag>` без сохранённой авторизации. Публикация сама по себе не подтверждает публичную видимость.

## Обязательные проверки разработки

Перед завершением каждого изменения выполните из корня репозитория:

```sh
make check-fast
```

Команда устанавливает зависимости из lockfile, собирает интерфейс и выполняет `go test -race -count=1 ./...`. Для изменений интерфейса дополнительно выполните полный gate:

```sh
make check
```

Он также устанавливает Chromium и запускает браузерные тесты Playwright. Требуются GNU Make, Go и Node.js указанных выше версий, C toolchain для Go race detector; для браузерных тестов — системные библиотеки Chromium. На Linux их можно установить один раз: `npm --prefix web ci && npm --prefix web exec -- playwright install-deps chromium` (может потребоваться sudo). Любая ошибка останавливает проверку; пропуски и retries не используются.

Backend-тесты проверяют авторизацию, сессии, ключи агентов, SQLite/миграции, MCP и запуск CLI. Браузерные тесты проходят пользовательские сценарии на настоящем Go-сервере со свежей временной БД, не используя рабочий `./data` или сервер на 8081. При изменении поведения обновляйте соответствующие тесты; исправления непокрытых ошибок сопровождайте regression test.

Для узкой проверки после установки зависимостей и сборки интерфейса: `go test ./internal/web` либо `npm --prefix web test`. Это не заменяет соответствующий итоговый gate.

GitHub Actions запускает `make check-fast` на каждом push и pull request. Браузерные тесты выполняются только локально через `make check`; в GitHub Actions они не запускаются. Чтобы запретить слияние без быстрой проверки, в ruleset/защите основной ветки необходимо сделать статус **Required checks** обязательным и требовать pull request. Workflow сам не изменяет настройки защиты репозитория.

Подробности и планируемая архитектура — в [docs/architecture.md](docs/architecture.md).
