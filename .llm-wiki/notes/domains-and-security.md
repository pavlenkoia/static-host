# Домены и безопасность

Базовый домен задаётся установкой; в текущей установке — `uc.afbmarket.ru`. Панель, MCP и upload используют отдельные hostname. [Короткие адреса](/sources/short-hostnames-capability-upload.md) имеют вид `https://<slug>.sites.uc.afbmarket.ru`: slug постоянно хранится отдельно от ID и формируется из имени сайта; совпадения получают числовой суффикс, удалённые имена не переиспользуются. При запуске существующим сайтам назначается slug; прежние ID-hostname остаются рабочими. [Публичный wildcard ingress](/sources/wildcard-ingress.md) настроен и проверен сквозной публикацией. Собственные домены развёрнуты 2026-11-26; выпуск сертификата реальному собственному домену ещё не проверен.

Свои домены подключаются без отдельной TXT-проверки. Основной путь: CNAME на системный адрес конкретного сайта. Сервис проверяет соответствие выбранному сайту, уникальность hostname, направление трафика и готовность HTTPS.

Для корневого домена допустим A/AAAA на разрешённые адреса ingress; AAAA только при работающем IPv6. Flattening/ALIAS обычно проверяется как IP. Принятый риск: совпадение IP не подтверждает право пользователя на домен. Другой пользователь может первым заявить незакреплённый домен, уже указывающий на общий edge. Не называть эту проверку доказательством владения.

Подтверждённый hostname глобально уникален, неподтверждённые заявки не резервируют его. Приостановленный hostname остаётся закреплённым; автоматического переноса нет. Неизвестные и отключённые hostname не обслуживают случайный или старый сайт. Пользовательские wildcard-домены и DNS proxy не поддерживаются.

Lifecycle: pending_dns → provisioning_tls → active; после подтверждённой смены DNS возможен suspended. Active требует проверки HTTPS на всех опубликованных адресах, ошибки видны пользователю. Системному wildcard TLS нужен DNS challenge и совместимый Caddy-модуль.

Кабинет объясняет подключение через статусы и пошаговые DNS-инструкции: CNAME и A/AAAA — альтернативы для одного имени. «Подключён» означает готовый HTTPS; настройки такого домена свёрнуты, даты скрыты под «Подробности проверки». Окно можно закрыть крестиком, кнопкой или Escape; при прокрутке управление остаётся видимым, пустой список не заменяется загрузкой при фоновом опросе.

Карточка сайта показывает собственные домены со статусами и ссылками для подключённых адресов; системный адрес подписан отдельно. Данные перечитываются при загрузке списка сайтов и закрытии окна управления доменами.

Для своих доменов выбран On-Demand TLS с обязательным внутренним `ask` endpoint приложения. Единый `compose.yaml` задаёт явные маршруты и fallback для hostname вне маршрутов остальных сервисов. Явные маршруты других сервисов сохраняют приоритет, их домены и управляющие hostname нельзя привязывать к сайтам. Глобальный `on_demand_tls`/`ask` необходимо заранее задать в управляемой конфигурации Caddy; HTTP/HTTPS `x-ports` с `x-caddy` не совмещается. Генерируемый Caddyfile не редактируется.

Адрес внутреннего ask не настраивается переменной окружения: при включённых ingress IP приложение слушает порт 8082, в локальном режиме только на loopback.

Добавление домена меняет только БД: DNS и уникальность проверяются заранее, `ask` читает подготовленное разрешение и отказывает для неизвестных, отключённых доменов и при ошибках. Caddy выпускает сертификат при первом handshake, хранит и продлевает его. Ни деплой сервиса, ни reload Caddy на каждый домен не нужны. `ask` не авторизует каждый HTTP-запрос: после удаления привязки приложение немедленно прекращает отдачу сайта, независимо от сохранённого сертификата. Неограниченный on-demand запрещён. Привилегированный domain-controller не требуется.

[Проверка совместимости](/sources/domain-compatibility.md) подтвердила поддержку по исходникам Uncloud 0.21.0 и runtime-тесту Caddy 2.11.7 с внутренним CA. После production-развёртывания 2026-11-26 проверены межнодовая доступность ask, отказ неизвестному hostname, HTTP fallback и доступность существующего опубликованного сайта. Реальный собственный домен и публичный ACME для него ещё не проверены. Образ выпущен штатным workflow в GHCR и развёрнут из `ghcr.io/pavlenkoia/static-host:latest`.

Пользовательский HTML изолирован от управляющих hostname. Все поддомены всё ещё имеют общую site-границу afbmarket.ru: host-only __Host- cookies, CSRF и Origin checks обязательны; общие domain cookies недопустимы. Upload требует лимитов, безопасной распаковки, квот и проверки прав. Секреты не сохранять в документации/wiki.
