# Инфраструктура и рабочий процесс

Локальная основа на Go слушает loopback `127.0.0.1:8081` по умолчанию; адрес задаётся `--listen`. Без базового домена разрешён только числовой loopback; при заданном домене HTTP listener может обслуживаться через TLS-прокси с сохранением Host. Доступны health, Vue-кабинет владельца и MCP с ключами агентов; сессии и хеши ключей хранятся в SQLite. Сборка и ограничения описаны в [локальном этапе](/sources/local-owner-mcp.md). Хостинг сайтов и развёртывание пока не реализованы. Uncloud разворачивает сервис, не каждый пользовательский сайт. Основной процесс не получает Docker/Uncloud sockets и SSH. Для доменов выбран Caddy On-Demand TLS с внутренним `ask` endpoint приложения, без привилегированного domain-controller. Fallback и `ask` настраиваются один раз через управляемые глобальные параметры Caddy и `x-caddy` сервиса; конкретная конфигурация на Uncloud 0.21.0 ещё требует проверки. Генерируемый Caddyfile вручную не редактировать.
Новые токены зашифрованы в SQLite; файл `agent-key-encryption.key` требуется сохранять вместе с базой при переносе и резервном копировании. Процесс с доступом к обоим файлам может раскрыть токены.
Вход единственного владельца: фиксированный `admin` и обязательный runtime-секрет `STATIC_HOST_ADMIN_PASSWORD` (12–72 байта). [Пароль окружения](/sources/env-admin.md) заменяет CLI bootstrap: пароль не хранится в SQLite, при запуске сессии сбрасываются, существующие MCP-ключи сохраняются. Секрет задаётся при развёртывании, не при сборке образа.

Наблюдения 2026-11-25: Uncloud 0.21.0, машины edge-1 и uc-1; Caddy caddy:2.11.7 работает единственной репликой на публичном edge-1; Uncloud volumes отсутствуют. edge-1 имеет 1 CPU, около 1 ГБ RAM и 11 ГБ свободного диска. Ресурсы uc-1 не исследованы. Настроенный кластерный домен был uc.tiangroup.su, а не новый проектный uc.afbmarket.ru. Wildcard DNS и DNS-модуль Caddy не проверены.

Уточнение по [проверке совместимости](/sources/domain-compatibility.md) 2026-11-25: версии обеих нод Uncloud 0.21.0 и работающего Caddy 2.11.7 подтверждены командами чтения. Нужные механизмы есть в исходниках этого тега Uncloud. Изолированный Caddy той же сборки подтвердил приоритет явных маршрутов, `ask`, добавление домена без reload, отказ удалённой привязке и работу HTTP endpoint Uncloud. Это снимает неопределённость базовой совместимости, но не заменяет проверку итогового deploy, публичного ACME, DNS, wildcard TLS, межнодовой доступности будущего `ask` и readiness приложения. Production не менялся.

`edge-1` остаётся публичным прокси с Caddy. По [первому deploy](/sources/first-deploy.md) приложение закреплено на `uc-1` (2 CPU, 2 GiB RAM, около 17 GiB свободного диска); постоянный каталог /var/lib/static-host имеет владельца 10001:10001 и права 0700. Caddy проксирует по внутренней сети, публичный IP приложению не нужен. Автоматический перенос приложения и данных не предполагается. Размещение без HA; резервная копия вне ноды приложения и проверка восстановления ещё не настроены. Backup не заменяет пользовательский rollback. Основание размещения: [динамические домены и размещение](/sources/dynamic-domains.md).

Подготовлены [контейнер, Compose и workflow выпуска](/sources/container-release.md): одна реплика с постоянными данными, явные panel/mcp маршруты и smoke до публикации в GHCR. По [решению о ручном выпуске](/sources/manual-image-release.md) Container image запускается только через workflow_dispatch из main, без автоматической сборки на push/PR; перед публикацией выполняются быстрые проверки и smoke. [Первое развёртывание](/sources/first-deploy.md) подтвердило healthy-сервис, публичный образ, доверенный HTTPS, вход владельца и MCP initialize; публикация сайтов пока не реализована.

Документация — docs/architecture.md; правила — корневой AGENTS.md. Локальная wiki — стандартная .llm-wiki/. Начинать запрос знаний с index.md, затем секционных индексов. Raw-снимки неизменяемы; новые источники импортировать через okf ingest, изменения записывать через okf update с timeline и log. Подключение инструкций выполнено через okf wire --agent codex. Основание исправления: [стандартное подключение OKF](/sources/agent-workflow-correction.md). Wiki не является вторым независимым архитектурным контрактом.

Тесты обязательны: до завершения каждого изменения выполнить `make check-fast` (сборка Vue и Go-тесты с race detector без кэша); для изменений интерфейса дополнительно выполнить полный `make check` с Playwright на настоящем Go-сервере с временной БД. По [решению о проверках PR](/sources/pr-only-checks.md) workflow Checks запускает быстрый gate только на pull_request, не на push; ручной выпуск образа также выполняет быстрый gate. Браузерные проверки остаются локальными, workflow Browser checks удалён по [решению пользователя](/sources/no-browser-ci.md). Админка не считается главным или критичным компонентом. Для блокировки merge отдельно требуется обязательный статус Required checks в защите ветки. Подробнее — [обязательные проверки](/sources/development-checks.md). Изменения production/DNS и разрушительные действия требуют разрешения. Проверка документации: `okf index .llm-wiki`, затем `okf lint .llm-wiki --strict-frontmatter`.

Основание: [начальные решения](/sources/project-decisions.md). Связанные страницы: [модель продукта](/notes/product-and-publication.md), [домены](/notes/domains-and-security.md).
