## Изменения только документации

Если меняются только `README.md`, `AGENTS.md`, Markdown-файлы в `docs/` и проектная память `.llm-wiki/`, достаточно:

```sh
make check-docs
```

Требуются GNU Make, Python 3 и установленный CLI `okf` из skill `llm-wiki-okf`. Gate проверяет наличие начального H1, закрытие fenced code blocks и существование целей локальных inline Markdown-ссылок в README, AGENTS и `docs/**/*.md`, затем выполняет `okf lint .llm-wiki --strict-frontmatter`. Он не запускает npm, сборку UI, Go-тесты и сетевые запросы; не проверяет URL внешних ресурсов, fragment anchors и смысловую актуальность описаний. Код внутри fenced/inline code не считается ссылками. Wiki проверяется штатным OKF lint, а не как обычная документация, поскольку её пути и raw-снимки имеют другую семантику.

Исключение не распространяется на код, конфигурацию, Makefile и скрипты проверок. При смешанных изменениях выполнить `make check-docs` вместе с применимым gate приложения. В CI правила не меняются: PR по-прежнему проходит `make check-fast`.

## Изменения приложения и инструментов

Перед завершением остальных изменений выполните из корня репозитория:

```sh
make check-fast
```

Команда сначала выполняет `make check-format`, затем устанавливает зависимости из lockfile, собирает интерфейс и выполняет `go test -race -count=1 ./...`. Проверка формата обязательна и в CI, поскольку workflow вызывает тот же gate. Для изменений интерфейса дополнительно выполните полный gate:

```sh
make check
```

Он также устанавливает Chromium и запускает браузерные тесты Playwright. Требуются GNU Make, Go 1.27.4 или новее, Node.js 24, C toolchain для Go race detector; для браузерных тестов — системные библиотеки Chromium. На Linux их можно установить один раз: `npm --prefix web ci && npm --prefix web exec -- playwright install-deps chromium` (может потребоваться sudo). Любая ошибка останавливает проверку; пропуски и retries не используются.

Backend-тесты проверяют авторизацию, сессии, ключи агентов, SQLite/миграции, MCP и запуск CLI. Браузерные тесты проходят пользовательские сценарии на настоящем Go-сервере со свежей временной БД, не используя рабочий `./data` или сервер на 8081. При изменении поведения обновляйте соответствующие тесты; исправления непокрытых ошибок сопровождайте regression test.

Для узкой проверки после установки зависимостей и сборки интерфейса: `go test ./internal/web` либо `npm --prefix web test`. Это не заменяет соответствующий итоговый gate.

Workflow **Checks** запускает `make check-fast` только на pull request, не на push. При ручном выпуске образа `make check-fast` также выполняется перед сборкой. Браузерные тесты выполняются только локально через `make check`; в GitHub Actions они не запускаются. Чтобы запретить слияние без быстрой проверки, в ruleset/защите основной ветки необходимо сделать статус **Required checks** обязательным и требовать pull request. Workflow сам не изменяет настройки защиты репозитория.

## Форматирование Go

Исходники и тесты в `cmd/` и `internal/` оформляются стандартным `gofmt`:

```sh
gofmt -w cmd internal
make check-format
```

`check-format` ничего не переписывает: выводит пути неотформатированных файлов и завершается ошибкой; ошибки разбора Go также останавливают gate. Проверка выполняется до npm и тестов. Новых зависимостей не требуется — `gofmt` входит в Go toolchain.

Не склеивайте независимые операторы через `;`: проверки ошибок и изменения состояния должны читаться как отдельные шаги. Длинные вызовы и литералы оформляйте многострочно. Форматирование не должно менять поведение; сгенерированные файлы вручную не исправляются.


## Карта кода

| Путь | Ответственность |
| --- | --- |
| `cmd/static-host/` | Запуск, сборка зависимостей, завершение по сигналу |
| `internal/config/` | Флаги, окружение и публичные origins |
| `internal/httpserver/` | Разделение поверхностей по Host и пути |
| `internal/auth/`, `internal/store/` | Авторизация, шифрование ключей, SQLite |
| `internal/web/` | HTTP кабинета и встроенная сборка UI |
| `internal/mcpserver/` | MCP transport и инструменты |
| `internal/publication/` | Архивы, загрузки, атомарная публикация, выдача файлов |
| `web/src/`, `web/e2e/` | Vue UI и Playwright-сценарии |
| `deploy/caddy/`, `scripts/` | Образ ingress и container smoke |

Интерфейс использует общие Vue-примитивы `web/src/components/ui/`, Tailwind CSS и семантические токены `web/src/style.css`. Сборка UI создаёт `internal/web/dist/`; генерируемые файлы вручную не редактируются.

При изменениях обновляйте тематическую страницу в `docs/` и проектную память через OKF. Не сохраняйте в документации секреты и пользовательское содержимое. Источники команд: [Makefile](../Makefile), [Checks](../.github/workflows/check.yml), [Container image](../.github/workflows/image.yml).
