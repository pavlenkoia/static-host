## Состояние и остановка

`GET /healthz` возвращает `ok\n`, `HEAD /healthz` — те же заголовки без тела. Container healthcheck обращается к loopback listener. Это проверка ответа процесса, а не внешнего DNS, TLS, доступности сайта или пригодности резервной копии.

После разрешённого развёртывания проверяйте отдельно trusted HTTPS панели и реального опубликованного сайта. MCP без ключа должен отказывать в авторизации; управляющие endpoints не должны быть доступны на hostname сайта. Тестовую публикацию и её удаление согласуйте: это изменение данных.

SIGINT/SIGTERM запускают завершение HTTP-сервера с таймаутом 5 секунд. Каждый запуск удаляет браузерные сессии; MCP-ключи сохраняются. Работать должны один процесс и одна реплика: не запускайте две копии с общей SQLite.

## Пароль и ключи

Единственный логин — `admin`. `STATIC_HOST_ADMIN_PASSWORD` обязателен при каждом запуске (12–72 байта), не сохраняется в SQLite или журналах. При перезапуске используется новое значение окружения; команд bootstrap/reset нет. Изменение `.env` без перезапуска не меняет окружение работающего процесса.

Новые значения ключей зашифрованы в SQLite через AES-256-GCM. Файл `agent-key-encryption.key` необходим для их повторного просмотра; храните его с правами 0600. Проверка MCP использует хеш ключа. Доступ к БД и файлу шифрования позволяет раскрыть сохранённые значения; это не защита при полном захвате сервера.

Не выводите upload URL, bearer-ключи, пароль, session cookie, содержимое `.env` и окружение контейнера в логи или документацию. Доступ к Docker daemon позволяет увидеть runtime-переменные, включая пароль.

## Резервное копирование и восстановление

Сервис не предоставляет автоматизированный backup/restore workflow. Размещение без HA, автоматического переноса данных нет. Backup не является пользовательским rollback сайта.

Сохраняйте согласованным набором весь каталог данных: SQLite, `agent-key-encryption.key` и дерево файлов сайтов. В контейнере это `/data`, на ноде по Compose — `/var/lib/static-host`. Не копируйте только основной файл работающей SQLite и не считайте такую копию согласованной.

Консервативный порядок для оператора после отдельного разрешения на простой:

1. Остановить единственную реплику и убедиться, что никто не пишет в каталог.
2. Скопировать весь каталог с сохранением прав и владельца в защищённое хранилище вне ноды приложения. Секрет окружения хранить отдельно в хранилище секретов.
3. Запустить сервис с тем же каталогом; проверить health и HTTPS сайта.
4. Проверить восстановление в изолированной установке совместимой версии, с отдельным каталогом и без production-маршрутов. Не подключать восстановленную копию одновременно к исходной БД.
5. Проверить вход, файлы сайта и доступность сохранённых MCP credentials без раскрытия их значений.

Это порядок действий, не свидетельство выполненной проверки восстановления. Не заменяйте production-данные копией и не удаляйте файлы вручную без явного разрешения.

## Диагностика

| Симптом | Что проверить |
| --- | --- |
| Процесс не запускается | Пароль 12–72 байта, числовой listener, валидность домена, права каталога и доступность ключа шифрования |
| Кабинет отвечает 403 | Совпадение Host/Origin с конфигурацией; wildcard bind не разрешает произвольный Host |
| MCP отвечает 401 | Ровно один `Authorization: Bearer`, срок/отзыв/удаление ключа |
| PUT не принимается | Использование URL целиком с token, точный Content-Type, срок grant, действительность выдавшего ключа |
| `upload_busy` | В сервисе уже есть pending/receiving/ready upload; готовый upload нужно опубликовать либо дождаться истечения |
| `generation_conflict` | Другой publish изменил сайт; перечитать generation и согласовать снимок |
| `invalid_archive` | Непустой корневой `index.html`, отсутствие внешней папки, запрещённых путей/ссылок и превышений лимитов |
| `storage_full` | Свободное место на файловой системе данных, включая резерв сверх размеров архива и распаковки |
| Сайт отвечает 404 | Публикация завершена, hostname верен, файл существует; нет SPA fallback и листинга каталогов |
| Health работает, HTTPS сайта нет | Wildcard DNS, ingress-маршрут, Cloudflare-модуль/токен Caddy и выпуск сертификата |

Не удаляйте SQLite, ключ шифрования или каталоги сайтов как способ «починить запуск». Временные и осиротевшие данные после сбоя обрабатывает приложение; ручная очистка требует отдельного разбора.

## Граница безопасности

HTML сайта — недоверенный активный контент; его нельзя обслуживать на управляющем hostname. Разделение на поддомены одной регистрируемой зоны не создаёт полной site-изоляции. Перед публичным запуском проверьте существующие приложения с domain cookies. Кабинет использует host-only session cookie, проверку Origin и CSRF-защиту; не вводите общие cookies для панели и сайтов.
