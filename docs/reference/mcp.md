# MCP и публикация

[Навигация](../README.md) · [Конфигурация](configuration.md) · [Архитектура](../architecture.md)

## Подключение и ключи

Transport — MCP Streamable HTTP на `/mcp`: локально `http://127.0.0.1:8081/mcp`, с базовым доменом `https://mcp.<домен>/mcp`. Каждый MCP-запрос требует `Authorization: Bearer <ключ>`. Ключ создаётся в кабинете владельца и даёт полный доступ к его сайтам; scopes пока нет.

Новые ключи по умолчанию бессрочные; в кабинете можно задать срок в днях, повторно показать или скопировать значение, отозвать или удалить ключ. Отзыв и удаление действуют на следующий запрос. Значения старых ключей, выпущенных до поддержки повторного просмотра, восстановить нельзя.

Go SDK v1.8.0: при протоколе по умолчанию `2026-07-28` `ClientSession.Ping` не добавляет обязательные метаданные и получает 400. Для этого клиента можно явно выбрать `ClientSessionOptions{ProtocolVersion: "2025-11-25"}`. Поддержка версий сервером не ограничена.

## Инструменты

| Инструмент | Вход | Результат |
| --- | --- | --- |
| `sites_create` | `name` | `site` нового черновика |
| `sites_list` | `{}` | `sites` владельца |
| `sites_get` | `site_id` | `site`, включая текущую `generation` |
| `sites_delete` | `site_id` | `deleted`, `site_id`; удаление без восстановления |
| `uploads_create` | `site_id`, `format` (`zip` или `tar.gz`), `expected_generation` | Upload grant |
| `sites_publish` | `site_id`, `upload_id`, `expected_generation`, `idempotency_key` | `site` после публикации |

`expected_generation` обязателен в обоих вызовах. Используйте значение из актуального объекта сайта. `idempotency_key` — 1–128 ASCII-символов из букв, цифр и `._:-`, уникальный для новой операции владельца.

## Полный цикл

1. Вызовите `sites_create` либо `sites_get` существующего сайта.
2. Сохраните `site_id` и `generation`, вызовите `uploads_create`.
3. Grant содержит `upload_id`, `upload_url`, `method`, `headers`, `format`, `expires_at` и `limits`.
4. Вне MCP передайте **полный** архив по `upload_url` методом `PUT`, с выданным `Content-Type` (`application/zip` или `application/gzip`). **MCP bearer при PUT не нужен**: секретная capability находится в URL. Не публикуйте URL и не помещайте его в логи.
5. После успешного PUT вызовите `sites_publish` с тем же `expected_generation`, полученным `upload_id` и новым `idempotency_key`. Используйте тот же MCP-ключ, которым создан upload.
6. Откройте URL из результата публикации. PUT сам не меняет работающий сайт.

При потере ответа `sites_publish` повторите точно те же аргументы и `idempotency_key`: сервер возвращает сохранённый результат, не создавая ещё одну публикацию. Тот же ключ с иными аргументами даёт `idempotency_conflict`. При `generation_conflict` перечитайте сайт и согласуйте изменения: нельзя молча подменять generation ради перезаписи.

Upload одноразовый. Отзыв, удаление или истечение выдавшего ключа запрещают передачу; действительность ключа проверяется до и после приёма. Истёкший или испорченный upload требует нового grant.

## Архив и лимиты

| Ограничение | Значение |
| --- | --- |
| Сайтов | 100 |
| Активных uploads на весь сервис | 1, включая готовый к публикации |
| Архив | 100 МиБ |
| Распакованное содержимое | 250 МиБ |
| Файлов | 10 000 |
| Записей архива, включая каталоги | 20 000 |
| Опубликованный объём владельца | 5 ГиБ |
| Срок upload | 15 минут, включая публикацию |

Обязателен непустой `index.html` в корне архива, не внутри дополнительной папки. Недопустимы абсолютные пути, traversal, обратные слеши, повторяющиеся записи, symlink/hardlink и специальные файлы. Глубина пути ограничена 64 сегментами, длина — 4096 байт. Сервер проверяет свободное место с резервом, поэтому формального соблюдения квоты недостаточно при заполненном диске.

## Адреса и выдача

Slug строится из имени: нижний регистр, транслитерация кириллицы, дефисы; совпадения получают `-2`, `-3`, … . Публичный hostname постоянен и не переиспользуется после удаления. Существующим сайтам без slug имя назначается при запуске; прежние ID-hostname сохраняются. Префикс `s-` зарезервирован для ID.

Каждая публикация полностью заменяет снимок: отсутствующие файлы исчезают. Истории содержимого и rollback нет. Выдача поддерживает GET/HEAD, каталог с `index.html`, но не directory listing и не SPA fallback. Файлы получают `Cache-Control: no-cache` и `X-Content-Type-Options: nosniff`.

## Ошибки

Ошибки инструментов имеют `isError` и объект `error` с `code` и `message`. Основные коды: `invalid_request`, `site_not_found`, `generation_conflict`, `idempotency_conflict`, `upload_busy`, `upload_not_ready`, `upload_expired`, `quota_exceeded`, `storage_full`, `service_unavailable`.

HTTP PUT возвращает JSON-ошибку; в частности: неверный/неизвестный capability — 404, недействительный ключ — 401, истечение — 410, неготовое состояние — 409, неверный Content-Type/архив — 400, большой архив — 413, нехватка диска — 507. Не повторяйте PUT вслепую после начала приёма.
